Decisions the owner should revisit.

- **Graph vs linear look alike in simple chats (Phase 3).** A fork copies the parent prefix and nothing creates CONTEXT edges, so graph mode differs from linear only when a child's copied prefix is trimmed/compacted (graph still reads the source session) or when `session.metadata["context_edges"]` is injected. A small `/context link` command would make the difference visible in the UI.
- **Graph token budget.** `AgentLoop` passes `max_tokens=self.context_window_tokens` to the graph engine (the full window). Linear relies on the compaction pointer instead. Consider a smaller dedicated budget.
- **Orphaned graph files.** Old `<data>/context_graph/**/*.json` files are no longer read or written; safe to delete.

- **Embedding choice for Phase 4 (decided 2026-10-18: local hashed bag-of-words "for now").** Options considered: (1) hashed bag-of-words: pure Python, no dependency, deterministic, but matches shared words only, not meaning; (2) local sentence-transformers model: real semantic quality and offline, but adds torch and a model download, against the minimum-code rule; (3) provider embeddings API: best quality, but needs a key and network, nanobot has no embedding client, adds cost and a failure mode. The embedder sits behind one interface; revisit (2) or (3) if the demo needs real semantic matches.

- **Graph/hybrid after a slash command (fixed 2026-10-19).** Command turns were counted as replayable by the graph engine, which made graph and hybrid fall back to linear (and skip hybrid recall) whenever only command turns followed the archive pointer, and shifted node ids when a command sat mid-replay. They are now excluded up front (tests added). Consequence to know: in `graph` mode a chat whose ancestors are all compacted now replays *nothing* from them (empty history plus the archived summary the loop already adds), where before the failure path accidentally gave it linear history. That is the Phase 3 design, but it can look sparse; `hybrid` recall is the intended remedy.
